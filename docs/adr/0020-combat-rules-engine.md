# ADR-020: Combat rules engine — validated action resolution, effects, typed damage, and the dying state

## Status

Accepted — 2026-07-18. Amended the same day (second slice, same PR): reaction
prompts, incapacitation gating, the available-actions read, and archive v3 — see
"Amendment" below.

## Context and decision drivers

A forensic comparison of two archived runs of the same encounter (a manual GM run and a rules-aware recreation driven through the integration API) showed that the engine recorded mechanics but did not own them: the manual run performed two Frenzy attacks plus a Greataxe attack in one round-one turn with no Rage active, resolved Extra Attack as unrelated single rolls, applied crocodile damage to a raging barbarian with no resistance, never created the Bite grapple as state, and used seven manual heals (five of exactly 1 HP) as a stand-in for a dying state. None of this was blocked, warned about, or guided. The automated recreation proved the low-level API could emulate the rules — at a cost of 120 commands for a three-round fight, with the rules living in an external script instead of the server.

The owner's direction for this milestone: combat should "just work" — the legal action is the easiest path, unavailable actions are clearly explained, and the GM keeps an explicit, audited override for homebrew and intentional exceptions. This supersedes the earlier blanket posture that action economy is "tracked, never enforced" (ADR-008's reference level; BUILD_PLAN §13.4 "do not hard-block extra actions"), which these runs showed delegates too much rules bookkeeping to the GM's memory. Design precedent for the typed-mechanics vocabulary was validated against MIT-licensed sibling projects (notably cbgfx/beholden's typed-effects compendium schema) — patterns only, no code or data reuse.

## Considered options

- Keep reference-level tracking and improve display only: preserves the old posture but cannot prevent any of the observed error classes.
- A high-level "execute action" API that atomically rolls every attack, applies damage, and resolves prompts in one transaction (the gap-analysis report's original proposal): maximally guided, but reshapes the one-command-one-roll journal/archive contract, breaks replay of existing archives, and removes the GM's between-rolls target choice.
- Validated resolution over the existing command surface (chosen): `action.resolve` stays one roll burst per command, but validates against engine-owned state before rolling, with a per-encounter enforcement mode and an audited override.

## Decision

The server owns combat rules state and validates structured action resolution against it (extending ADR-008, whose representation rules are unchanged: declarative vocabulary, bounded dice grammar, no imported executable code).

1. **Structured mechanics vocabulary** (additive-optional on `ActorDefinition` schemaVersion 1, per ADR-007): `attack.count` (Extra Attack, beams), `attack.criticalBonusDice` (Savage Attacks), `multiattack` composition, `onHit` condition riders with escape DCs and size caps, `targetRules`, `grants` (self effects like Rage/Reckless with typed modifiers, durations, and on-end grants), `requiresEffectTag`, `uses` (per turn/encounter/long-rest with shared pools), and typed defense lists (`damageResistances`/`damageImmunities`/`damageVulnerabilities`/`conditionImmunities`). The SRD ETL emits these from confident statblock patterns only (126 of 178 Multiattacks, 47 on-hit riders, 146 monsters with typed defenses); everything else stays inert prose.
2. **Rules modes with an audited override.** Each encounter carries `rulesMode`: `strict` (default — invalid structured resolutions are rejected with machine-readable `blocked {rule, message, overridable}` details), `assisted` (allowed, conflicts logged as warnings), `freeform` (no checks). Any rejection can be bypassed by resending with `override: {reason}`, which is prominently recorded in the combat log (kind `override`) and the journal. An actor whose stat block has a prose-only Multiattack degrades action-slot violations to warnings even in strict mode — the engine never polices rules it cannot see. Manual commands (`turn.use`, amount-only damage, `actor.set-condition`, `actor.set-hp`) remain free escape hatches; un-marking the action slot also clears the open compound-action instance.
3. **Action instances.** Resolving an action-activation action with a free action slot consumes the slot once and opens an instance of remaining components: a generic `attack` pool for `attack.count` (so Extra Attack may legally mix weapons), actionId-keyed components for `multiattack` (Bite + Tail). Further resolves consume components; exhausted instances reject with "no attacks remaining". One command still equals one roll burst, preserving journal/archive semantics and sequential target choice.
4. **Persistent effects.** `Actor.effects` holds engine-owned `EffectInstance`s (name, tags, source links, duration, typed modifiers, linked conditions, escape DC, on-end grants, `endsWithTag` cascades). The engine ends them: durations expire at the source's turn start, a source at 0 HP releases what it sustains (grapples, its own Rage), `endsWithTag` cascades (Frenzy's marker ends with the Rage, firing its Exhaustion exactly once), encounter end sweeps the fight's combatants (on-end grants fire — a documented simplification), and grants from the same source actor + action refresh rather than stack. Sweeps are scoped to the current initiative so parked scenes keep their effects. On-hit riders auto-apply conditions at resolve time — the same owner-approved carve-out class as save auto-apply.
5. **Typed damage at apply time.** `actor.apply-damage` accepts optional typed `parts`; the server applies immunity → resistance-halving → vulnerability (resistance and vulnerability on one type cancel) from definition defenses plus active effects, then temp HP, and returns/logs the per-part breakdown ("17 bludgeoning → 8, resistance: Rage") — never a silent adjustment. The bare `amount` stays exact for manual corrections. Pending saves carry typed parts and halve per part on success.
6. **Advantage aggregation with explanations.** Attack resolution aggregates advantage/disadvantage sources (effect modifiers — `attack-advantage` is evaluated only on the bearer's own turn, Reckless semantics; incoming-attack-advantage on the target; prone with the 2024 distance rule via authoritative token distance; restrained/poisoned/blinded/stunned/paralyzed/petrified/unconscious; unconscious + adjacent upgrades hits to crits), cancels per 5e, rolls `2d20kh1/kl1`, and reports every contributing source. An explicit GM `rollMode` choice wins.
7. **The dying state.** Damage dropping a player character to 0 applies Unconscious + Prone and initializes death saves (instant death on overflow ≥ max HP); damage while dying adds failures (two on a crit; stability breaks and counters restart from zero per the SRD reset rule); `death-save.roll` runs the d20 pipeline (20 → 1 HP + conscious; 1 → two failures; three successes → stable with counters reset; three failures → dead); healing or set-hp above 0 clears the dying state (Prone stays). Non-player combatants at 0 are "defeated" (effects they sustain end; no death saves). All five HP entry points share this machine.
8. **Command surface.** New commands `effect.add`, `effect.end`, `death-save.roll`, `encounter.set-rules-mode`, `actor.rest` (long rest: effects end first, HP/uses/dying reset, Exhaustion −1) ride the shared operations layer, both transports, the OpenAPI contract, and the archive journal like every other command (ADR-016 no-fork). Timeline restores and the dirty comparator cover effects, death saves, and spent uses; player projections strip effect source ids, mask hidden source names, and expose limited-use spending only for the claimed character.

## Consequences and tradeoffs

The published `turn.use` semantics changed from "(tracked, never enforced)" to "manual toggle; structured resolution validates per rules mode" — integrations replaying old journals (or scripting freely) should set `freeform` mode first, and a mid-flight encounter upgraded under this release parses to `strict` and may see first rejections until the GM overrides or switches modes. Enforcement applies only on the acting combatant's own turn; off-turn resolutions (opportunity attacks, GM improvisation) stay ungated. Prose-only mechanics remain unenforced by design.

Explicitly unsupported after this milestone (documented, not accidental): reaction triggers beyond hit-by-attack/half-damage (opportunity attacks, Parry-style AC responses, damage-taken triggers), triggered features (Relentless Endurance, Dark One's Blessing, Halfling Lucky, Sneak Attack *eligibility* — only its once-per-turn pool ships), concentration and target-scoped effects (Hex), movement/range/reach/line-of-sight legality, rolled grapple escapes (the escape DC displays; ending the effect is manual), incapacitated-ends-grapple (only 0 HP releases), player-invoked `action.resolve`, per-encounter monster death policies, ruleset (2014/2024) declarations and import compatibility levels, structured recharge/legendary actions, and beam-count-by-level expressions (static counts in definitions). Non-turn-scoped always-on attack advantage (e.g. Invisibility) needs a new modifier flag — do not reuse `attack-advantage` for it. The remaining-work roadmap lives in `docs/product/rules-engine-followup-assessment.md`.

## Amendment — 2026-07-18 (second slice, same PR)

9. **Reaction prompts.** Declared reactions (`reaction: {trigger: "hit-by-attack", response: "half-damage"}` — Uncanny Dodge) become first-class pending prompts on the pendingSaves template: a qualifying hit (structured attack, damage > 0, reactor's reaction free, reactor not incapacitated, mode not freeform) parks its rolled typed damage on `combat.pendingReactions` *instead of* the runner's apply button. `reaction.answer` (GM anyone; a player their claimed character) applies the damage either halved per part (use — spends the reaction) or in full (decline); the halving happens before defenses, so resistance still applies on top. `reaction.dismiss` (GM) drops a prompt without applying — the escape hatch for damage entered by hand. Prompts persist across turn changes until answered so parked damage is never silently lost; player projections carry only the player's own prompts, source ids stripped and hidden sources masked.
10. **Incapacitation gates the economy.** An actor with Incapacitated (or a condition that includes it: Paralyzed, Petrified, Stunned, Unconscious) violates `condition.incapacitated` for any action, bonus action, or reaction — handled by the same strict/assisted/override ladder as every rule.
11. **Available-actions read.** `GET /game/actors/{actorId}/available-actions` (and the `actor:available-actions` socket read) reports per-action availability computed by the *shared* `evaluateActionEconomy` — the exact evaluation strict resolution enforces, so the report can never drift from enforcement. Rows carry machine-readable violations, uses remaining, and open-instance counts. GM-grade any combatant; a player only their claimed character (availability names stat-block internals). Target-specific rules need a target and are not pre-checked.
12. **Archive v3.** Encounter archives additively gain `postEncounterState` — the state after `encounter.end` ran (combat cleared, end-of-fight effect sweeps and their on-end grants landed). `finalState` (the last live picture) is unchanged; the fight's true aftermath was previously unrecorded.

## Mobile, security, and visibility impact

All validation, rolls, and effect lifecycle run server-side; phones and desktops see identical outcomes. Blocked rows stay tappable in the GM UI — the server rejection opens the one-tap override dialog, so the client never gates (server authority, CLAUDE.md rule 2). New projection fields are explicit allowlists: effects reach players without source actor/action ids (hidden sources masked as "A hidden threat"), a hidden combatant's turn instance and per-turn uses project as idle, limited-use spending travels only to the owning player, and the public viewer projection is unchanged.

## Migration / reversibility

All state additions are additive-with-defaults on schemaVersion 1: existing campaigns, turn snapshots, and archives parse unchanged, and old journals replay under `freeform` mode. The bundle regeneration is deterministic and reviewed in git. Reverting enforcement is a one-line default change (`rulesMode` to `freeform`) with no state migration; removing the mechanics fields would require a content-schema review per ADR-007.
